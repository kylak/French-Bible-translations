● Oui, c'est largement automatisable ! La partie la plus mécanique (placement
  des marqueurs) peut l'être à 100%, et la partie linguistique (détermination

  Pipeline proposé

  [traduction brute]
         ↓ Étape 1 (manuel/AI)        ← format bbcccvvv original
  [ORIG.txt : versification d'origine]
         ↓ Étape 2 (manuel/AI)        ← appliquer frontières 1551 ST
  [ADJ.txt : texte réorganisé, SANS marqueurs]
         ↓ Étape 3 (script pur)       ← AUTOMATISABLE À 100%
  [FINAL.txt : avec ⋄ et ⌇]
         ↓ Étape 4 (script pur)       ← validation
  [rapport d'audit]

  Ce qui est 100% scriptable

  Script 1 — validate_counts.sh (déjà fait par toi)

  Compare le nombre de versets par chapitre entre la traduction et ST.txt. Sort
  la liste des chapitres divergents.
  for book ch ; do diff_count = MARTIN_n - ST_n ; ... done

  Script 2 — insert_markers.sh (le plus utile)

  Entrées : ORIG.txt (versification originale) + ADJ.txt (texte réorganisé en
  1551 ST sans marqueurs).
  Sortie : FINAL.txt avec ⋄N et propagation automatique.

  Algorithme :
  1. Pour chaque chapitre, lire les versets de ORIG et ADJ, concaténer en deux
  longs strings
  2. Vérifier que les deux strings sont identiques (sinon le texte a été
  modifié, pas juste réparti)
  3. Pour chaque frontière MARTIN dans ORIG, calculer sa position dans le string
   concaténé
  4. Localiser cette position dans ADJ → soit elle aligne avec une frontière
  1551, soit elle est à l'intérieur d'un verset
  5. Si MARTIN_N ≠ ADJ_N à cette position (renuméro) OU si la position est
  intérieure (déplacement), insérer ⋄N (N = numéro MARTIN)

  C'est purement mécanique — string matching + comptage de caractères. Pas de
  NLP.

  Script 3 — audit_markers.sh

  Entrées : FINAL.txt + ORIG.txt.
  Sortie : rapport des incohérences.

  Vérifie :
  - Compte verset par chapitre = ST.txt ✓
  - Chaque frontière déplacée a un ⋄ correspondant
  - Chaque ⋄N a un N plausible (N proche du numéro 1551)
  - Cohérence de propagation : si offset détecté, tous les versets suivants
  jusqu'à fin de chap ont leur marqueur
  - Paires ⌇ équilibrées (un à la fin de N, un au début de N+1)

  Script 4 — cross_check_spreadsheet.sh

  Entrées : versification_spreadsheet.csv + FINAL.txt.
  Sortie : pour chaque ligne du CSV, indiquer si un marqueur est présent dans la
   traduction (et de quel type).

  Permet de voir d'un coup d'œil : "les 118 cas connus du CSV, voici lesquels
  ont nécessité un marqueur dans MARTIN, lesquels non".

  Ce qui n'est pas 100% scriptable (mais assistable)

● Excellente question — c'est l'étape charnière où il faut vraiment décider.
  Voici ce que recouvre ADJ.txt et les options pour l'obtenir.

  Ce qu'est ADJ.txt

  C'est le fichier où :
  - le texte est exactement celui d'ORIG.txt (aucun mot ajouté ou enlevé)
  - les frontières de versets ont été repositionnées pour matcher 1551 ST
  - aucun marqueur ⋄/⌇ n'est encore présent

  Dans ton workflow actuel, c'est exactement sources/MARTIN - 
  1707/step2/1.verisifying_manually/output.txt ou la version juste avant le
  commit b203ecd (le fichier complete-Bible/MARTIN - 1707.txt avant que tu
  commences à ajouter les marqueurs).

  La transformation ORIG → ADJ se décompose en deux choses

  (a) Décider OÙ se trouvent les frontières 1551 ST dans le texte français

  C'est la partie non purement scriptable. Pour chaque entrée du CSV concernant
  ta traduction, il faut localiser dans le français la séquence qui correspond
  aux mots grecs frontière. Exemple Rm 1:29-30 :
  - CSV : 45001029,Rom. 1:29,start,ψιθυριστὰς,whisperers
  - Donc 1551 v30 commence aux « whisperers » = « Rapporteurs » en MARTIN
  - Donc dans MARTIN v29 actuel, la frontière 1551 v29/v30 est entre « moeurs. »
   et « Rapporteurs, »

  (b) Appliquer le repositionnement (pur script)

  Une fois (a) connu, le script qui produit ADJ.txt est mécanique : il concatène
   le texte du chapitre, puis le redécoupe aux positions indiquées.

  Comment obtenir (a)

  Trois niveaux d'automatisation possibles :

  Niveau 1 — Manuel guidé par le CSV (ce que tu as fait pour MARTIN)

  Tu lis le CSV ligne par ligne, et pour chaque entrée applicable à ta
  traduction, tu identifies la position dans le français à l'œil. Très fiable

  Détection automatique des chapitres à examiner

  Deux signaux mesurables sans NLP, qui couvrent toutes les divergences :

  1. Nombre de versets différent entre ORIG et ST pour ce chapitre → forcément
  split ou merge à appliquer.
